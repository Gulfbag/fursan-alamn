# فرسان الأمن للحماية — الموقع وبوابة العرض

نسخة مراجعة محافظة على الهوية البحرية/الذهبية والشعار الأصلي، بمحتوى عربي وإنجليزي مبني محليًا، وواجهة تشغيلية **تجريبية ببيانات افتراضية فقط**.

## تشغيل وتحقق

يتطلب Node.js 22.12 أو أحدث ضمن إصدار مدعوم.

```bash
npm ci
npm run check
npm start
```

تعمل المعاينة على `http://localhost:8080`. افتراضيًا `LEAD_SINK=disabled`، فلا يحفظ الموقع طلبات في Google Sheets. نموذج الطلب يتحقق من المدخلات ثم يجهز رسالة WhatsApp ليرسلها المستخدم بنفسه؛ لا يفتح WhatsApp ولا يدعي حفظ الطلب تلقائيًا.

يمكن ضبط البيئة بتصدير المتغيرات، أو استخدام `node --env-file=.env server/index.mjs` بعد إنشاء ملف محلي من `.env.example`. لا ترفع `.env` أو مفاتيح أو وثائق داخلية إلى Git.

## الصفحات

- الرئيسية العربية `/` والإنجليزية `/en/`؛ توجد صفحات مستقلة للخدمات والقطاعات والحلول والتعريف بالشركة والتراخيص والتواصل والخصوصية وطلب العرض.
- لكل خدمة ومقال مسار فعلي، وللمدونة بحث وتصنيف محليان. `/index-en.html` القديم يحول إلى `/en/`، ولا يوجد تبديل لغة إلى صفحة عربية باسم إنجليزي.
- البوابة التجريبية `/platform.html` و`/en/platform.html`؛ `noindex`، ولا توجد هوية أو قاعدة بيانات أو فيديو حي أو ذكاء توليدي متصل فيها.
- تبديل أدوار العمليات/المشرف/الحارس/العميل **تصفية عرض فقط**؛ جميع البيانات المزروعة افتراضية ومتاحة في مصدر المستودع العام. ليست هذه حماية إنتاجية للبيانات.
- البلاغات وقوائم التحقق ومراجعة إشارة فيديو مصطنعة والتقارير وسجل التدقيق والمسودات المحلية تعمل في ذاكرة الجلسة وتعود للحالة الأصلية عند إعادة التحميل.

## البنية

| المسار | الاستخدام |
|---|---|
| `src/data/content.mjs` | بيانات الشركة والخدمات والمقالات من مصدر موحد |
| `scripts/build-site.mjs` | توليد صفحات الموقع وSEO والروابط والأيقونات الثابتة |
| `src/styles.css` | رموز الهوية والخطوط المحلية وTailwind 4 |
| `scripts/build-portal.mjs` و`src/platform/` | بناء البوابة ومنطق العرض والبيانات الافتراضية |
| `assets/` | أصول محلية محسنة، بلا Tailwind CDN أو مكتبة أيقونات كاملة في المتصفح |
| `server/` | خادم الملفات العام وAPI الطلبات وموصل Sheets الاختياري |
| `server/integration/` | جسر استقبال خاص بـCloud Run IAM وGoogle ID Token، معطل الحفظ والمزامنة افتراضيًا |
| `infra/staging/` | مولد خطة أوامر للمراجعة فقط، يتطلب منطقة اختبار معتمدة ويرفض استهداف الإنتاج |
| `server/ai/assistant.mjs` | موصل تلخيص إلى Google Cloud، معطل وغير مكشوف كـHTTP API |
| `tests/` و`scripts/check-site.mjs` | اختبارات خادم ونطاق وDOM وروابط وبيانات الصفحات |
| `Dockerfile` و`cloudbuild.yaml` | حزمة Cloud Run مستقبلية؛ ملف Cloud Build يبني فقط ولا ينشر |

الصفحات المولدة تُحفظ في Git لتبقى الاستضافة الثابتة ممكنة. عند التعديل غيّر المصادر ثم نفذ `npm run build`؛ لا تعدل HTML المولد وحده. لم تُنقل ملفات السياسات أو المعمارية أو الشهادات الأصلية أو صور المستخدم إلى المستودع.

## النطاق والاستضافة

يبقى `https://www.fapc.sa` النطاق الأساسي الافتراضي للمحتوى حتى اعتماد قرار توحيد النطاقين. يمكن ضبط canonical وsitemap وhreflang **وقت البناء فقط**:

```bash
SITE_ORIGIN=https://www.example.sa npm run build
```

في Docker استخدم `--build-arg SITE_ORIGIN=https://www.example.sa`، وفي Cloud Build مرر `_SITE_ORIGIN`. ضبط `APP_ORIGIN` في التشغيل لا يعيد بناء SEO؛ هو قيد Origin لنموذج الطلب فقط.

هذه النسخة لا تستبدل `www.fursanalamn.com` أو `fapc.sa` ولا تغير DNS أو IAM ولا تنشر على `fursan-alamn-prod`. المسار المقترح بعد الوصول والاعتماد: مراجعة → staging → اختبارات قبول وتشغيل → blue/green وخطة رجوع → قرار إطلاق.

## التكامل الحقيقي: ما أُعد وما بقي

- **أُعد:** API يتحقق من طلبات الويب، وموصل Google Sheets يكتب صفًا واحدًا بـRAW بعد تفعيل صريح وهوية ADC. لا يحاول استخراج Spreadsheet ID من لقطة الشاشة ولا يقرأ الملف الرئيسي.
- **التوصية:** ملف استقبال طلبات منفصل، ثم مزامن خاص إلى Fursan-Master-Database. صلاحية Editor على ملف Sheets ليست append-only على تبويب واحد. المزامن **غير منفذ** في هذا الإصدار.
- **أُعد:** موصل تلخيص نصوص مصرح بها عبر هوية Google Cloud، بناتج مسودة ومراجع ومراجعة بشرية، دون أدوات كتابة أو فيديو. لم يُختبر مع نموذج حي ولم يُربط بالبوابة.
- **أُعد:** `LEAD_SINK=bridge` لجسر Google Cloud Run خاص، بهوية خدمة وallowlist وتحقق توقيع وعقد ثابت ومهلة تشمل الرد. تشغيل receiver ممكن من نفس الحاوية بأمر `node server/integration/receiver-index.mjs`؛ معطل افتراضيًا ويمنع مزامنة Master. يرفض staging اتصال Sheets المباشر من الموقع، ويمنع فهرسة معاينة الاختبار.
- **بقي:** جرد موارد Google Cloud ومخطط Master Database، SSO/MFA وتفويض خادمي فعلي، تخزين وأثر تدقيق دائمان، حصص موزعة وتسوية التكرار، إعدادات بيانات وخصوصية واعتماد المنطقة والنموذج، ومزامن المصدر الرئيسي واختبارات Pilot.

راجع [دليل Google Cloud وGoogle Sheets](docs/google-cloud-and-database.md)، و[عقد الجسر المحمي](docs/secure-master-bridge.md)، و[خطة Staging](infra/staging/README.md)، و[حدود موصل الذكاء الاصطناعي](docs/ai-integration.md). لا تعني هويات IAM للتكامل وجود صلاحيات تشغيلية للمستخدمين داخل البوابة، وهذه تجهيزات مراجعة وليست شهادة أمن أو امتثال أو إثبات تشغيل إنتاجي.

## الاختبارات والقيود

`npm run check` يعيد البناء، يشغل اختبارات Node/DOM مع بيانات واستجابات محقونة، ويفحص الصفحات والروابط والمراسي واللغات وSEO وغياب الموارد التنفيذية الخارجية. لا ترسل الاختبارات بيانات إلى Google أو WhatsApp.

CI يعمل على طلبات الدمج وعلى `main` بصلاحية قراءة فقط، ويفحص التبعيات وتطابق المخرجات ويبني الحاوية؛ **لا يوجد نشر تلقائي في سير CI المضاف**. قد توجد استضافة GitHub Pages قائمة خارج هذا السير، لذلك يبقى طلب الدمج للمراجعة ولا يُدمج تلقائيًا.

الأرقام النظامية المنشورة مصدرها وثائق المستخدم؛ فئة الترخيص تمثل السعة المرخصة وليست عدد موظفين حاليًا. تسجيل حماية البيانات لا يثبت وحده الامتثال الكامل، وشهادة جدير تستلزم تحقق صلاحيتها الدوري. سياسات الخصوصية والنصوص القانونية مسودات تستلزم مراجعة المالك قبل تشغيل جمع البيانات.

## النواة الجديدة للعمل بلا ورق

`/operations.html` و`/en/operations.html` إضافة جديدة منفصلة عن `/platform.html` القديمة: واجهة API حقيقية للطلبات والعملاء والمهام والمستندات الداخلية، دون بيانات عرض أو حفظ أعمال في localStorage أو تبديل دور محلي. هوية IAP موقعة + ربط أدوار خادمي + قاعدة Firestore مسماة + معاملات وتدقيق ومنع تكرار وversion conflicts. افتراضيًا `OPS_ENABLED=false`؛ استضافة Pages لا تشغل عمليات حفظ، وإعداد تفعيل غير صالح يرفض startup بدل إخفائه خلف health ناجح.

نواة Cloud تحتاج تهيئة القاعدة والصلاحيات ومنطقة معتمدة واختبار SDK/ADC حي؛ لا تثبت اختبارات الذاكرة/SDK المحقون هذه الجاهزية. لا دور Owner/Editor للتطبيق ولا وصول Master أو Drive أو Gmail. مدير النواة الداخلية ليس تغييرًا في IAM أو حساب البريد. بريد الموقع الموحد في مصدر المحتوى هو `info@fapc.sa` بناءً على توجيه المالك، وليس اعتمادًا لإرسال البريد تلقائيًا.

المساعد الإجرائي المحلي ليس LLM. موصل Vertex يظل معطلًا إلى أن تعتمد معالجة البيانات والنموذج والمنطقة والصلاحية؛ لا endpoint عالميًا أو إرسال خارج المنطقة المعتمدة تلقائيًا. مخرجاته مسودات فقط، والاعتماد الرقمي داخلي وليس توقيعًا قانونيًا.

راجع [دليل النواة ودورة العمل وحدود القبول](docs/paperless-operations.md) وإعداداتها في `.env.example`. المرفقات/OCR والتوقيع الإلكتروني القانوني وPDF والإشعارات والمزامنة الخارجية ليست وظائف مفعلة في الإصدار الأول. لا ترحيل بيانات أو حذف سكربتات قديمة أو دمج/إطلاق إنتاج تلقائيًا.
